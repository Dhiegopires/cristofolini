A pipeline where stage and urgency aren't the same signal

Collabboard is a concept B2B CRM workspace built around daily sales decision-making. Most pipeline boards track one thing — what stage a deal is in — and expect urgency to live in someone's head. Collabboard makes urgency an explicit, separate signal, and renders the same pipeline three different ways depending on what the person looking at it needs to do.

01

The problem

Most CRM pipelines collapse two different questions into one signal. Stage answers "where is this deal in the process." It says nothing about "does this deal need attention right now." When the interface only tracks stage, urgency has to live in a rep's memory — which works for a handful of deals and breaks down past that.

A deal stuck in Negotiation for nine weeks and a deal that just arrived both render identically if stage is the only thing the board shows.

Collabboard keeps stage as the structural axis — it still decides which column a card sits in — but adds temperature as a second, independent signal a rep sets and the board displays without it changing the deal's position. Where and how urgent stop being the same question.

02

Stage and temperature, decoupled

Every card on the pipeline board carries a Hot, Warm, or Cold chip alongside its stage column. A deal in Proposal can be Hot because the buyer just asked for a contract redline, or Cold because procurement went quiet three weeks ago. Same stage, opposite urgency — and now the board shows the difference instead of hiding it.

Stage only

The board groups deals by where they are. A rep scanning columns sees process, not priority. Finding what needs attention today means opening cards one by one.

Stage + temperature

The column says where. The chip says how urgent. A rep can scan for Hot chips across every column in one pass, regardless of which stage those deals happen to be in.

Rejected approach Calculating temperature automatically from a days-since-last-activity threshold. Rejected: automatic flags get ignored once a few false positives appear — a deal can be legitimately quiet during a procurement freeze without being dead. A rep-set signal carries judgment a timer can't, even though it depends on reps actually updating it.
03

One pipeline, three lenses

The same set of deals renders three ways, and none of them is the "real" view. The board shows flow — cards moving across stages, good for a rep working the pipeline day to day. The table shows everything sortable and filterable by deal, company, owner, value, and close date — what a manager needs for a forecast review across all 47 open deals at once.

Board

Spatial, stage-grouped, built for scanning and moving cards. Answers "what's happening across the pipeline right now."

Table

Dense, sortable, filterable by any column. Answers "which deals match this specific criteria" — the question a forecast review actually asks.

Forcing a manager's review into the board, or a rep's daily work into the table, both technically work and both fight the task. The data is identical; only the shape changes with the job.

04

Home as daily briefing

The home view deliberately inverts the board's axis. Where the pipeline groups by stage, "Today's Priorities" groups by required action — a high-priority follow-up, a demo to schedule, a proposal due today — regardless of which stage each one belongs to. A rep opens one list instead of scanning every column for what's on fire.

Four KPI cards sit above it at equal size: Pipeline Value, Open Deals, Closing This Month, Win Rate. That's a different decision than giving one metric the lead, and it's deliberate here rather than inconsistent — these four numbers answer four different questions for different moments in the day, not four competing claims on the same decision. Equal weight is correct when nothing should out-rank the others; hierarchy is for when one signal should drive the next action, which none of these four single-handedly does.

05

The page that replaces a meeting

Opening a single deal brings the activity timeline, a deal summary (probability, source, created date, last activity), and the people involved into one layout. Anyone — a manager covering for a rep on leave, a rep picking up a deal mid-cycle — can read the full state of a deal without a handoff call.

The timeline reads like a log, not a feed: calls, proposals sent, emails, demos, and stage changes in one chronological line. Mixing activity types in a single stream, rather than splitting them into separate tabs, keeps the sequence of what actually happened intact.

Resolve fragmented deal context across tools and inboxes is a leading cause of low day-to-day CRM adoption by reps (Forrester, 2022)
06

Reflections

The home view's four equal KPIs look like they contradict BrightFlow's "pick one metric" principle — they don't, but I should make that explicit sooner. Hierarchy is for when one number should drive the next action. Equal weight is for when several numbers answer genuinely different questions for different roles. Both are real principles; the failure mode is applying one where the other is needed, not picking the "wrong" one in isolation.

Temperature only works if reps actually keep it updated. A manually-set signal is more honest than an automatic one, but it inherits the same risk every manual CRM field has: it decays into being ignored a few weeks after launch. I'd want a lightweight nudge — surfacing temperature alongside the activity log, so updating it feels like part of logging a call rather than a separate chore.

Moving between the three lenses isn't designed yet. Clicking a card opens the detail page, but does a filter applied on the table carry over if a rep switches to the board? I didn't design that continuity, and in a real product it's exactly the kind of seam that makes multiple views feel like multiple tools instead of one workspace.
