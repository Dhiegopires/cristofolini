NorthPay: Onboarding as a product surface.

Onboarding as a product surface.
Onboard

Every field sits between the user and the product.

Financial products have to collect sensitive data before anyone sees value, which makes onboarding the most fragile part of the flow. Every field is there because regulation requires it. The order those fields appear in is a design decision.

Role
Product Designer
Type
Concept project
Scope
Account setup, KYC, first use
Duration
8 weeks
01

Problem

Three parties, one fragile sequence.

Users ask why it takes so long. The business asks where people drop. Compliance needs every field. The fix is not fewer fields, it is how they are presented.

  • 19%abandon when forced to create an account before seeing value (Baymard, 2024)
  • 3phases: account type, identity, verification
  • 6steps, all visible from the first screen
02

Flow & IA

Account type first. Every field after depends on it.

Choosing the account type before any form opens removes the worst failure: switching type mid-form and losing everything already typed.

03

Wireframes

One job per screen.

Low fidelity locked structure and order first. A rejected version put the account toggle next to the first fields; people switched type and lost their data. Separating the decision from the data is a data-loss prevention pattern, not a preference.

04

Key screens

A decision, then a form.

The first screen asks one thing. Personal details come grouped, with the stepper always showing what is left.

05

States

Designed for the moments that fail.

Errors appear field by field as people leave each input, not on submit. Verification has a pending state with a timeline, so waiting reads as expected, not broken.

06

First use

A checklist instead of an empty dashboard.

After verification, people land on a setup checklist with one clear next action instead of every option at once.

07

Reflections

What a real engagement would change.

KYC can span days, so the flow needs save and resume. Compliance was simulated here; with real AML rules I would map legal requirements before locking one question per screen. And the rejected layout deserved a fair build to test against, not a strawman.

Outcome

Designed against the known drop-off points.

A concept, not a shipped product: no live metrics. What it does measure is structure, each decision mapped to a documented cause of abandonment.

  • 0account gates before first value
  • 1question per screen
  • 6steps visible from screen one

Benchmarks: Baymard Institute, 2024.
