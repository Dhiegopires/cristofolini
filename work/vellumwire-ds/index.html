One layer changes per client. Nothing else.
System

Every new client started by rebuilding what already existed.

Each project began with a component library rebuilt from a blank file, even when the logic hadn’t changed. The real cost showed up at handoff: new names to interpret, new spacing to check, undocumented edge cases. What was missing was a layer between component and brand.

Architecture

Four layers, one allowed to change.

Structure stays fixed. Client decisions live in Brand, and components only read Semantic.

02

Palette

Ramps exist before any client does.

03

Brand

Same components, three brands.

A card, a button, an input and badges under three client brands. Ramp, typeface and radius change; component code doesn’t.

04

Components

Every state, in every brand.

Buttons, form controls and feedback, each with its variants and states, rendered from the same code under three brand layers.

Responsive

Mobile existed before anyone asked.

Size and type tokens resolve per breakpoint from the start. When Instivo needed a mobile stock view mid-project, it consumed the same tokens.

In production

Tested where it can break: real builds.

Refined under pressure on Instivo, including a mobile view that was never in scope. Afonso implements and hosts each build, which is what proves a layer holds.
