Instivo: A data workspace for multi-unit retail

A data workspace for multi-unit retail
Instivo

Letting store managers set their own rules without calling IT

Instivo is a SaaS for multi-unit retail, a company of around 50 people. I turned its business rules into a data workspace, a rule engine and a card-linked entity model that replaced six disconnected tools, and rebuilt the design system underneath.

Role
Product Designer (contract)
Period
Jun – Dec 2023
Team
Cross-functional, 5–10 per task
Research
Interviews with retail managers, usability tests
01

The problem

Six tools that never talked to each other

Employee records lived in spreadsheets, supplier orders went by phone and stock was counted by hand, across six tools that never talked to each other. A product dropping below 50 units triggered nothing: someone had to notice, call and follow up.

02

The product

The Data Workspace

The Data Workspace is where data is created and structured. Every form field, category and role across Instivo traces back to it. System workspaces feed the platform and cannot be deleted; free workspaces belong to the user.

03

Research

IT, managers and operators were blocking each other

I led discovery and interviews with retail managers alongside the PM. An IT rule could restrict a manager, and a manager rule could block an operator IT had allowed. Nobody found out until someone hit the block.

04

Decision

Products became linked cards

The brief asked for folders, but one product belongs to several categories at once and a folder holds it in one place. A linked card keeps a single record that plays a different role in each context.

05

Decision

A rule builder with four fixed parts

The first version used free text, and it failed in testing. What shipped is a fixed four-part schema that managers fill in from chips: operator, entity, condition, action.

06

Decision

Disabled controls say why

Critical workspaces show the delete control disabled, with the reason in a tooltip. Inherited rules appear read-only with their origin.

07

Fleet & Dock

Fleet and dock read the same records

Booking a dock needs a driver, a vehicle, a bay and a warehouse, all built in the Data Workspace. If a driver's license changes there, every booking picks it up, with no copied data and no integration layer in between.

08

Design system

Rebuilding the design system in four token layers

The inherited system had no tokens and no responsive logic. When mobile came mid-project, the semantic layer already resolved to it.

Results

Usability test results

Measured in usability testing with real users. In the test tasks, managers changed rules, categories and thresholds on their own, with no help from IT.

  • ~70%less configuration time
  • 5×faster new-unit onboarding
  • 6 → 1disconnected tools replaced by one workspace
